# 架构

[English](../architecture.md) | **简体中文**

GPU Ops 把集中式的策略与持久化，同节点本地的观测与执行分离开来，并刻意保持与直接 SSH 工作流的兼容。

## 组件

### 控制器

Go 编写的控制器负责：

- 托管 Web UI 与 HTTP API；
- 对管理员、分级运维、用户、Agent 和 HA 对端做鉴权；
- 启动时执行 PostgreSQL 迁移；
- 存储身份、账号映射、积分、价格、用量、策略、审计记录和运行时设置；
- 计算用量成本并排队下发节点动作；
- 运行月度积分、数据保留、提醒和 HA 定时任务；
- 读取系统级备份任务写入的状态文件。

### Node Agent

Go 编写的 Agent 运行在每个 Linux 计算节点上，采集硬件与进程状态、上报用量、轮询动作，并执行 CPU、内存、磁盘、GPU、进程和 SSH 策略。指标采集可以降权运行，但打包安装默认使用 root，因为策略执行需要操作系统级权限。

### Web UI

Vue 应用编译到 `web/dist`。控制器以同源方式托管静态文件与 API，简化了 cookie 与 CSRF 处理。开发模式下 Vite 把 API 流量代理到 `127.0.0.1:8080`。

### PostgreSQL

PostgreSQL 是控制面状态的权威存储。`database/migrations/` 中的迁移按顺序自动执行，数据库可用性是 `/readyz` 的一部分。

## 网络拓扑

```text
浏览器 ──HTTPS──> 反向代理 ──HTTP──> 控制器 Web 监听 (:8080)
                                          │
                                          └──> PostgreSQL (:5432)

Node Agent ──HTTPS + X-Agent-Token──> 控制器内部监听 (:8081)
HA 对端    ──HTTPS + X-HA-Token─────> 控制器内部监听 (:8081)
```

`internal_listen_addr` 是可选项。留空时，Agent、registry 和 HA 接口挂在 Web 监听上；配置后，这些接口迁移到独立监听，且必须提供证书与私钥。生产部署应启用独立内部监听，并将其限制在节点与控制器网络内。

公开 Web 监听自身不提供 TLS，请置于可信的 HTTPS 反向代理之后，并尽量绑定回环或内网地址。

## 主要数据流

### Agent 上报与动作下发

1. Agent 采样节点、用户、进程、GPU、磁盘、SSH 和服务状态。
2. 携带全局唯一 `report_id` 调用 `POST /api/metrics`。
3. 控制器去重、解析本地账号到平台身份、记录用量并计算成本。
4. 响应体与动作轮询接口下发待执行策略动作。
5. Agent 本地执行动作，并在后续上报中反映结果。

### 注册与账号映射

1. 用户注册并验证邮箱。
2. 管理员审核注册申请。
3. 用户登记已有节点账号，或申请开通新账号。
4. 控制器保存 `(node_id, local_username) → 平台用户` 映射。
5. 节点 registry 接口提供 SSH Guard 状态与账号列表。

### 积分与策略执行

用量成本按策略从节点专属积分、结转积分和通用积分中扣除。余额状态可能触发预警、CPU/内存限制、GPU 限制或进程终止。启用强制策略前，运维方应先在 `dry_run` 模式下校验计费。

## 鉴权域

| 角色 | 机制 | 范围 |
| --- | --- | --- |
| 浏览器用户/管理员 | 签名的 HttpOnly 会话 cookie + CSRF 头 | Web 与角色允许的 API 路由 |
| 引导/运维脚本 | `Authorization: Bearer <admin_token>` | 超级管理员 API 访问 |
| Node Agent | `X-Agent-Token` | 内部指标、动作与 registry 路由 |
| HA 对端 | `X-HA-Token` | 内部 HA 状态 |
| 匿名客户端 | 无 | 健康检查、就绪检查、公开设置、注册与登录 |

每节点 token 可以先以审计模式引入，待所有节点迁移完成后再强制。legacy token 提供一个有限的轮换窗口。

## 信任边界

- 控制器管理员可以修改策略并触发破坏性的节点动作。
- 以 root 运行的 Node Agent 可以检查进程并修改所在节点的操作系统控制项。
- PostgreSQL 保存运营与身份数据；拥有数据库访问权等同于拥有控制面权限。
- SMTP 凭据以运行时设置形式存放在 PostgreSQL 中，数据库备份需同等保护。
- 按用户名查询余额与用量的接口需要凭据：运维 token、管理员会话，或该用户本人的会话。节点侧辅助脚本使用节点本地文件中的 Agent token 鉴权，该文件对节点用户可读——请把它当作节点级凭据，而不是用户级凭据。
- 备份仓库与 HA 备机是独立的特权系统，不应与主控制器共用全部凭据或同一故障域。

## 仓库边界

GPU Ops 不包含生产数据库、TLS PKI、反向代理、身份提供方、邮件服务、NFS 服务端、容器镜像仓库或监控栈。本仓库提供应用组件与参考脚本，基础设施集成与策略决策由运维方负责。

## 设计约束

- Linux 与 systemd/cgroup 行为存在差异，必须在每个节点镜像上验证策略执行能力。
- `node_id` 是运维方定义的稳定标识，不要求是 IP 地址或 SSH 端口。
- 迁移只向前执行；数据库回滚需要经过验证的恢复流程。
- HA 同步是运维自动化，而不是共识协议。必须在网络与进程层面防止出现两个同时活跃的主控制器。
