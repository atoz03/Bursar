# 管理员指南

[English](../admin-guide.md) | **简体中文**

面向管理员与分级运维人员的模块、权限与安全规则说明。

## 角色

### 管理员（`admin`）

可访问全部模块：节点策略、积分、注册审核、账号映射、安全处置、邮件配置与容灾。

### 高级用户（`power_user`）

只能访问被权限位授予的能力：

| 权限位 | 授予的能力 |
| --- | --- |
| `view_board` | 运营看板 |
| `view_nodes` | 节点状态 |
| `manage_nodes` | 节点策略修改与远程动作 |
| `review_requests` | 注册与资料审核 |
| `manage_points` | 积分管理 |
| `manage_platform_users` | 平台用户管理 |

积分管理还被进一步细分——用户列表、按条件批量、全体批量、操作记录、月度配置和特殊规则各有独立权限位，因此可以只授予其中一项。

使用 `admin_token` 鉴权的请求会绕过上述全部检查，见[安全模型](security.md)。

## 节点管理

按节点配置的策略开关：

- **SSH 拦截** — 拦截未在平台登记的账号。
- **积分拦截** — 该节点是否扣分并施加限制。
- **计费参数** — GPU 单价与 CPU 核分钟单价，按节点单独设置。
- **独享用户** — 把节点保留给特定用户。
- **可见性** — 限定哪些高级用户可以看到该节点。

运维动作：立即同步、踢 SSH、清用户进程。这些动作会立即作用于节点，正式依赖前请先在 `dry_run: true` 下验证。

节点列表会在节点 ID 旁用 emoji 标记风险，页面顶部横幅汇总近 7 天有安全事件的节点。

## 积分管理

- 调整单个用户的通用积分、结转积分或节点专属积分。
- 对全体用户批量加减积分。
- 按学位类别配置月初重置，并支持按用户的特殊规则覆盖。
- 配置结转上限。该上限是结转池的累计上限，不是每月新增上限。
- 配置每月最大欠费上限，超过后会触发强制清理该用户全部进程。

扣费顺序为 **节点专属积分 → 结转积分 → 通用积分**。节点专属积分不参与月度结转，也不会按月过期。

每次积分操作都会记录时间、操作、对象、变动值和积分类型。

## 账号与访问

**平台用户。** 状态管理、拉黑与解黑、删除与恢复、重复身份排查。

**账号映射。** 维护 `(node_id, local_username) → 平台用户` 的关系。换绑监测会标记在时间窗口内频繁换绑、或关联过多个平台账号的节点账号。被标记的账号带红点提示，可以直接在风险区执行拉黑。

**账号开通。** 开通节点账号，并以平台内密文加邮件提取码的方式下发凭据。若账号已映射到同一平台用户，二次确认后可以重新生成新密钥并重发。

**SSH 名单。** 白名单、黑名单与豁免名单统一管理，每条记录带有原因与来源。

## 安全事件

### 疑似恶意用户

这不是手工标签。控制器按 7 天窗口聚合 `node_security_events`，以 `node_id + username` 分组：

| 字段 | 含义 |
| --- | --- |
| `hit_count` | 窗口内触发次数 |
| `last_seen_at` | 最近触发时间 |
| `reason_hints` | 聚合后的理由 |
| `phenomena` | 疑似现象，如挖矿或 SSH 爆破 |
| `mining_suspected` | 窗口内是否命中过 `suspected_mining` |

只有带用户名的事件才会进入该名单。端口扫描事件通常没有关联用户，只出现在安全审计日志中。

默认条数上限：节点详情 200 条，安全事件页 500 条。

### 检测规则

下表取值来自 `controller/api.go` 中的常量。修改检测逻辑后请重新核对。

| 事件 | 触发条件 | 严重级别 | 冷却时间 |
| --- | --- | --- | --- |
| `suspected_mining` | 进程命令行命中挖矿关键词（`xmrig`、`cpuminer`、`minerd`、`ethminer`、`lolminer`、`nbminer`、`stratum`、`randomx`、`ethash` 等） | `critical` | 2 分钟 |
| `high_cpu_load` | 节点 CPU 负载达到总容量的 95% 及以上 | `warning` | 5 分钟 |
| `ssh_failed_login_spike` | 5 分钟内 SSH 失败登录超过 20 次 | `critical` | 30 分钟 |
| `ssh_bruteforce` | Agent 爆破信号处于激活状态 | `critical` | 30 分钟 |
| `abnormal_port_scan` | Agent 端口扫描信号处于激活状态 | `critical` | 30 分钟 |
| `disk_full_risk` | `/`、`/home` 或 `/mnt` 使用率 ≥ 98% 或剩余空间 ≤ 1 GB | `critical` | 10 分钟 |

冷却时间用于抑制同一节点上同类事件的重复写入，避免持续存在的状况刷屏。Agent 信号类事件在判定为解除前还会额外保持 10 分钟。

## 处置流程

### 疑似挖矿

1. 进入节点详情，查看疑似恶意用户名单与安全审计日志。
2. 核对命令样本与触发理由。
3. 拉黑账号、踢 SSH、清理其进程。
4. 检查该账号的映射历史与近期积分消耗。
5. 必要时通知用户并冻结相关账号。

### SSH 攻击突增

1. 查看 `ssh_failed_login_spike` 与 `ssh_bruteforce` 事件。
2. 把可疑账号加入黑名单。
3. 确认该节点已启用 SSH 拦截。
4. 复核白名单与豁免名单，避免豁免变成后门。

### 磁盘接近打满

1. 打开 `disk_full_risk` 事件，查看受影响分区与剩余空间。
2. 在节点详情中定位 `/home` 高占用用户。
3. 通知用户清理或代为清理，必要时临时限制该账号。

## 保持本文档准确

模块、权限、安全规则、阈值或处置动作发生变化时，必须同步更新本文档。触发更新的代码范围：

- `web/src/views/pages/Admin*.vue` — 模块行为
- `web/src/router/index.ts`、`web/src/views/Layout.vue` — 菜单与权限入口
- `controller/api.go`、`controller/database.go` — 安全规则、阈值、事件逻辑
- `config/controller.yaml` — 策略参数含义

每次发布前请确认：菜单路径一致、阈值表与代码一致、疑似恶意用户的定义与查询一致、新增模块已补充到本文档——并且两种语言都已更新。
